---

## Why Nextra?

When choosing a blogging framework, my primary requirements were:
1. **Markdown/MDX Native**: Writing posts should be as frictionless as writing standard Markdown, while allowing interactive React components where needed.
2. **Speed & SEO**: It must leverage Server Components and static site generation (SSG) for instant page loads.
3. **App Router Integration**: It should coexist with the rest of my portfolio website without bloating the main landing page.

Nextra v4 fit these criteria perfectly. Because it uses Next.js's App Router:
- We can route using the **Page File Convention** (`page.mdx`).
- We can define layout wrappers specifically for `/blog` using a nested `layout.tsx` file.
- The rest of the portfolio remains clean and isolated under its own route group.

---

## Code Example: Custom React Components in MDX

One of MDX's biggest advantages is the ability to write React components directly inside markdown files. For example, here's how a custom interactive component might be imported and rendered:

```tsx
import { useState } from 'react'

export function InteractiveCounter() {
  const [count, setCount] = useState(0)
  return (
    <button 
      onClick={() => setCount(count + 1)}
      style={{
        padding: '0.5rem 1rem',
        backgroundColor: '#008080',
        color: 'white',
        border: 'none',
        borderRadius: '6px',
        cursor: 'pointer'
      }}
    >
      Clicks: {count}
    </button>
  )
}
```

This flexibility allows me to build custom interactive visualizers for explaining technical concepts in future posts!
